# Mila 1.9.2-beta.1

- **English recordings on a remote server no longer come back with Hebrew words in them.** If your transcription server runs a Hebrew model (like ivrit.ai), it stays Hebrew-only no matter what language you pick — Mila asked it for English and it answered with Hebrew words spliced into the text. Settings → Models now has an **English model** field: set it to your server's multilingual model and English recordings go there, while Hebrew keeps using the accurate Hebrew one. Leave it blank if your server already handles every language (OpenAI's `whisper-1`, for example) and nothing changes.
- **The recording language is now Hebrew or English — Auto-detect is gone.** Mila picks which speech model to use *from* that choice, so "let it detect" meant guessing which specialist to ask before knowing what language it needed to handle — and on a Hebrew-specialised model it rendered English speech as Hebrew, the exact thing Auto-detect was supposed to prevent. Picking the language in the toolbar is one click and gives a noticeably better transcript. If you had Auto-detect selected, Mila switches you to Hebrew; existing Auto-detect recordings keep working and can still be re-transcribed.
- **Bring your own AI provider — no local CLI required.** Live AI summaries and action items can now talk to any OpenAI-compatible endpoint: OpenAI, Groq, OpenRouter, DeepSeek, Ollama Cloud, a local Ollama, or your own server. Previously Mila needed the `claude` or `cursor-agent` command-line tool installed on your Mac. Set it up in Settings → Live AI; the existing CLI option is untouched if you're happy with it.
- **Stopping a recording now really stops the AI.** The Live AI session kept running briefly after Stop — it could fire one more summary request against a recording Mila had already finished writing, and left its temporary session folder behind. Stop now shuts the session down immediately. Your summary is unaffected: it's regenerated from the complete transcript either way.
